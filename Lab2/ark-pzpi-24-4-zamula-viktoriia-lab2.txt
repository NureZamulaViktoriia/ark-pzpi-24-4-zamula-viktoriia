1 ЗАВДАННЯ
     Метою роботи є ознайомитися з процесом розробки серверної частини програмної системи, включаючи проектування бази даних (БД), розробку API для взаємодії з клієнтами, та перевірку (тестування) їхньої взаємодії. Оволодіти методами проектування діаграм UML та ER, розробки БД, програмної реалізації API, а також роботи з репозиторіями Git та створення технічної документації.
     

2 ОПИС ВИКОНАНОЇ РОБОТИ
     2.1 Опис інженерних рішень
     Серверну частину проекту побудовано за багатошаровою архітектурою, щоб розмежувати обробку запитів, бізнес-логіку та роботу з даними. Основою бекенду є Spring Boot, який надає REST API для взаємодії з Mobile- клієнтом, Web-клієнтом та IoT-пристроєм.
     Для забезпечення безпеки реалізовано гібридний підхід до автентифікації. Взаємодія з Web та Mobile захищена за допомогою безстанових JWT-токенів із обмеженим строком дії, для взаємодії з IoT-пристроями використовуються механізм перевірки HMAC-SHA256 підписів на базі симетричних ключів та перевірка часових міток для захисту від атак повторного відтворення.
     Взаємодія з базою даних MS SQL Server реалізована за допомогою Spring JDBC Template. Це рішення дозволило перенаправити частину складної бізнес-логіки та перевірок цілісності на рівень бази даних, такі як використання збережених процедур, функцій та тригерів, забезпечивши високу продуктивність та атомарність операцій. Для збереження конфігурацій, аудит-логів, результатів роботи LLM та GDPR-згод застосовано механізм локального кешування із записом у JSON-файл, що зменшує навантаження на базу даних для даних, які не потребують складних зв’язків.
     Інтеграція з моделлю штучного інтелекту Gemini виконана з дотриманням приватності: перед відправкою логів для формування підсумків та аналізу розбіжностей, система виконує знеособлення даних, гарантуючи, що модель працює виключно з загальними даними без доступу до конфіденційної інформації.

     Взаємодія з базою даних реалізована через шар репозиторіїв з використанням JdbcTemplate. У розділі Б.1 додатка Б наведено фрагмент з RequestRepository.java, який демонструє виклик збереженої процедури sp_InsertAccessRequest для створення заявки та виконання SELECT-запиту для перевірки перетину часових вікон.
     Обробка HTTP-запитів від клієнтів реалізована у REST-контролерах. У розділі Б.2 додатка Б наведено фрагмент з VisitorController.java, який демонструє процес прийому запиту на створення нової заявки та передачу управління до сервісного шару.
